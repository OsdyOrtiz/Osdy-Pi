# Native ODD TODO panel

## Objective
Ship an Osdy-owned model-facing TODO tool and interactive `/todos` panel backed by `odd/tasks/*.md`; the Markdown ledger, not Pi conversation history, is authoritative across sessions.

## Context and constraints
- Start from current `origin/main` at `f041cedab5d9967ccb07979180b6a6b31eec4812` on `feat/native-odd-todo` in a separate worktree. Do not merge the experimental `feat/todo-panel` branch, change the dirty original checkout, or publish.
- Preserve existing ODD prose and checkbox formatting; never choose an ambiguous task. Serialized Osdy writes and revision checks reject stale edits, but non-cooperating external writes racing between final check and atomic rename cannot be protected by a portable filesystem CAS; expose this limitation and do not claim cross-process transactional safety.
- Limit editing to validated files under the repository's `odd/tasks/`. One file is selected explicitly when more than one is present; task identity must not depend on its list index.
- Scope: read/list ODD task documents; edit checkbox status and add a checklist item in a selected document through a native tool and interactive panel. No separate conversation-history TODO store, automatic Engram mutation, or synchronization of arbitrary Markdown.
- Avoid registering a duplicate `todo` or `/todos` if upstream standalone rpiv-todo remains installed; document the required configuration choice.
- Technical artifacts default to English. Follow strict TypeScript, test-first for deterministic behavior, and Pi docs for extension and TUI APIs.
